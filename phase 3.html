7.1

User Interfaces

🔴 مهم

ماذا سندرس؟

User Interface — UI

وهي نقطة الاتصال بين المستخدم والنظام.

لا ننظر إليها كـ"تصميم جميل" فقط.

بل يجب أن تمكن المستخدم من:

Input←Interaction←Receive Output

بطريقة صحيحة.

أهم المصطلحات

User Interface — UIInputOutputScreenMenuFormUsabilityUser Satisfaction

لماذا الموضوع مهم؟

قد يكون عندك:

  • Database ممتازة.
  • Backend ممتاز.
  • Architecture ممتازة.

لكن الموظف لا يستطيع استخدام النظام بسهولة.

هنا يصبح النظام عمليًا سيئًا.

7.2

Human–Computer Interaction — HCI

🔴🔴 إتقان

HCI

يعني دراسة العلاقة والتفاعل بين:

Human

و

Computer System

💡

جعل النظام مناسبًا للطريقة التي يفكر ويتصرف بها الإنسان.

ماذا سندرس؟

  • كيف يرى المستخدم المعلومات؟
  • كيف يتنقل؟
  • ما الذي يتوقع أن يحدث عند الضغط؟
  • ما مقدار المعلومات المناسبة؟
  • كيف نمنع الأخطاء؟
  • كيف نعطيه Feedback؟
  • كيف نقلل التعقيد؟

لماذا مهم؟

تصميم الواجهة لا يبدأ من:

💡

ماذا يعجب المصمم؟

بل:

💡

كيف يستطيع المستخدم إنجاز عمله بشكل أسهل وأسرع وأقل أخطاء؟

7.3

Seven Habits of Successful Interface Designers

7.3.1 Understand the Business

قبل تصميم الشاشة:

💡

افهم الـBusiness.

لا تستطيع تصميم شاشة Warehouse إذا لم تفهم:

  • كيف يدخل المخزون؟
  • من يستخدم الشاشة؟
  • ما المعلومات المهمة؟
  • ما خطوات العمل؟

7.3.2 Maximize Graphical Effectiveness

استخدم العناصر البصرية بطريقة تخدم المستخدم.

ليس:

💡

المزيد من الرسومات = تصميم أفضل.

بل:

💡

كل عنصر بصري له وظيفة.

7.3.3 Think Like a User

ضع نفسك مكان المستخدم.

ليس:

💡

أنا كمبرمج أعرف أين يوجد الزر.

بل:

💡

هل المستخدم الجديد سيعرف أين يوجد؟

7.3.4 Use Models and Prototypes

قبل البرمجة النهائية نستخدم:

  • Models
  • Prototypes

حتى نختبر الفكرة.

7.3.5 Focus on Usability

Usability

مدى سهولة وفعالية استخدام النظام.

7.3.6 Invite Feedback

اعرض التصميم للمستخدم.

اسأله.

عدّل.

اختبر مرة أخرى.

7.3.7 Document Everything

لا تعتمد على ذاكرتك.

وثق:

  • Design decisions
  • Screens
  • Rules
  • Feedback
  • Changes

ما الذي سأستفيده؟

ستتعلم أن تصميم UI هو عملية:

Understand → Design → Prototype → Test → Feedback → Improve

وليس مجرد رسم شاشة.

7.4

Guidelines for User Interface Design

🔴🔴 إتقان

7.4.1 Create an Interface Easy to Learn and Use

يجب أن تكون الواجهة:

  • واضحة.
  • متوقعة.
  • سهلة التعلم.
  • لا تحتاج شرحًا مستمرًا.

7.4.2 Enhance User Productivity

التصميم يجب أن يجعل المستخدم ينجز عمله أسرع.

نقلل:

  • Clicks غير الضرورية.
  • إعادة إدخال المعلومات.
  • الخطوات المتكررة.

7.4.3 Provide Flexibility

ليس كل المستخدمين متساوين.

قد نحتاج:

  • أكثر من طريقة للتنقل.
  • Shortcuts.
  • تخصيص بعض الخيارات.

7.4.4 Provide Help and Feedback

النظام يجب أن يخبر المستخدم:

💡

ماذا حدث؟

مثل:

Order Saved Successfully

أو:

Invalid Customer Number

بدل أن يضغط المستخدم ولا يعرف هل العملية تمت أم لا.

7.4.5 Create an Attractive Layout and Design

الواجهة يجب أن تكون:

  • Organized
  • Consistent
  • Readable

لكن الجمال يخدم الوظيفة، وليس العكس.

7.4.6 Enhance the Interface

نستخدم عناصر UI المناسبة لتحسين التجربة.

7.4.7 Focus on Data Entry Screens

سندرس كيف نصمم:

  • Fields
  • Labels
  • Input order
  • Defaults
  • Lists
  • Confirmation
  • Required fields

7.4.8 Use Validation Rules

من أهم أجزاء UI Design.

قبل قبول البيانات نتأكد أنها صحيحة.

Sequence Check

هل البيانات بالترتيب الصحيح؟

Existence Check

هل الحقل الإجباري موجود؟

Data Type Check

هل القيمة من النوع الصحيح؟

Range Check

هل القيمة داخل النطاق؟

Limit Check

هل تتجاوز حدًا معينًا؟

Reasonableness Check

هل القيمة منطقية؟

Validity Check

هل القيمة موجودة ضمن القيم المسموحة؟

Combination Check

هل مجموعة القيم متوافقة مع بعضها؟

الهدف الأساسي:

💡

منع الخطأ قبل وصول البيانات إلى النظام.

7.4.9 Manage Data Effectively

من مبادئ التصميم الجيد:

💡

أدخل البيانات مرة واحدة كلما أمكن.

و:

💡

اجمع البيانات أقرب ما يمكن إلى مصدرها.

و:

💡

استخدم Automated Data Capture عندما يكون مناسبًا.

7.4.10 Reduce Input Volume

لا تطلب من المستخدم إدخال شيء يستطيع النظام معرفته بنفسه.

مثال:

إذا النظام يعرف:

Current Date

فلا تجعل المستخدم يكتب التاريخ يدويًا في كل عملية.

7.5

Source Document and Form Design

Source Document

وثيقة تستخدم كمصدر لإدخال البيانات.

مثل:

  • Order Form
  • Application Form
  • Invoice
  • Registration Form

ماذا سندرس؟

كيف نصمم Form بحيث:

  • الحقول واضحة.
  • ترتيبها منطقي.
  • المساحات مناسبة.
  • الأخطاء تقل.
  • المستخدم يعرف ماذا يكتب.

لماذا مهم؟

القاعدة:

💡

Garbage In → Garbage Out

إذا البيانات التي تدخل سيئة، النتائج ستكون سيئة مهما كان النظام ممتازًا.

  • Clear
  • Accurate
  • Readable
  • Useful

7.6.3 Types of Reports

Detail Report

يعرض التفاصيل.

Exception Report

يعرض الحالات غير الطبيعية أو التي تحتاج انتباهًا.

Summary Report

يعرض المعلومات الملخصة.

مثال

مدير المتجر قد لا يحتاج:

💡

كل فاتورة بالتفصيل.

بل:

Summary Report

عن إجمالي المبيعات.

بينما موظف المراجعة قد يحتاج:

Detail Report.

8.4

Data Design Terms

🔴🔴 إتقان

Entity

شيء نجمع عنه بيانات.

  • Customer
  • Product
  • Order

Field / Attribute

خاصية واحدة.

مثل:

Record / Tuple

مجموعة Fields تصف Instance واحدة.

Table

مجموعة Records منظمة.

8.4.2 Key Fields

Primary Key

يميز كل Record بشكل فريد.

مثال:

Customer_ID

Candidate Key

Field يمكن أن يكون Primary Key.

Foreign Key

Field يشير إلى Primary Key في Table أخرى.

Secondary Key

Field يستخدم للبحث أو Sorting ولكنه ليس Primary Key.

مفاهيم أخرى

  • Composite Key
  • Combination Key
  • Super Key
  • Alternate Key
  • Surrogate Key

المهم:

💡

لماذا نستخدم كل نوع؟

8.4.3 Referential Integrity

من أهم مفاهيم Database Design.

مثال:

Order يحتوي:

Customer_ID = 500

لكن Customer 500 غير موجود.

هذا يخلق مشكلة.

Referential Integrity تمنع العلاقات غير الصحيحة.

  • Update Problems

8.6.1 Standard Notation Format

نتعلم الطريقة المستخدمة لتمثيل البيانات أثناء Normalization.

8.6.2 First Normal Form — 1NF

الفكرة الأساسية:

💡

لا توجد Repeating Groups.

8.6.3 Second Normal Form — 2NF

يجب أن تكون 1NF.

ثم:

💡

جميع Non-Key Fields تعتمد على Primary Key بالكامل.

8.6.4 Third Normal Form — 3NF

يجب أن تكون 2NF.

ولا توجد:

💡

Non-Key Field تعتمد على Non-Key Field أخرى.

لماذا Normalization مهمة؟

لمنع مشاكل مثل:

Update Anomaly

نغير بيانات في مكان وننسى مكانًا آخر.

Insert Problems

لا نستطيع إضافة Record إلا بإضافة بيانات غير لازمة.

Delete Problems

حذف Record يؤدي إلى فقدان معلومات نحتاجها.
