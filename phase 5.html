12.2

Maintenance Tasks

🔴🔴🔴 إتقان كامل

هذا من أهم Topics في Chapter 12.

النظام بعد التشغيل يحتاج Changes.

الكتاب يقسم Maintenance إلى أربعة أنواع رئيسية.

12.2.1 Types of Maintenance

1. Corrective Maintenance

الهدف:

💡

Fix Errors

مثال:

Checkout Function بها Bug.

نقوم بإصلاحها.

السؤال

💡

هل أصلح مشكلة موجودة؟

إذا نعم، غالبًا Corrective.

2. Adaptive Maintenance

الهدف:

💡

Adapt the system to changed requirements or environment.

مثال:

  • دعم Regulation جديدة.
  • دعم Hardware جديد.
  • دعم New Business Requirement.
  • إضافة Capability بسبب تغير البيئة.

السؤال

💡

هل تغيرت البيئة أو الاحتياجات ونحتاج تكييف النظام؟

3. Perfective Maintenance

الهدف:

💡

Improve efficiency, usability, performance, or quality.

النظام يعمل.

لكن يمكن تحسينه.

مثل:

  • تحسين سرعة تقرير.
  • تحسين Workflow.
  • تحسين User Experience.

4. Preventive Maintenance

الهدف:

💡

Reduce the possibility of future failure.

مثل:

  • تنظيف أو إعادة تنظيم Code.
  • استبدال Component معرضة للفشل.
  • تحديث قبل أن يحدث Problem.

الفرق الذي يجب إتقانه

Typeالفكرة
Correctiveأصلح خطأ موجودًا
Adaptiveتكيف مع تغيير جديد
Perfectiveحسّن النظام
Preventiveامنع مشكلة مستقبلية

Configuration Management — CM

بدون CM يمكن أن يحدث:

  • Versions متضاربة.
  • Documentation قديمة.
  • تغييرات غير مصرح بها.
  • عدم معرفة ما الذي تغير.

  • System Changes
  • Versions
  • Documentation
  • Configuration
  • Releases
  • Baselines

12.4.1 Maintenance Releases

بدل نشر كل Noncritical Change وحدها:

نجمع Changes.

ثم نطلق:

Maintenance Release

مثال:

Version 1.0

ثم:

1.1

ثم:

1.2

أما Major Upgrade فقد يصبح:

2.0

الفوائد

  • Testing موحد.
  • عدد Releases أقل.
  • User Disruption أقل.
  • Documentation أسهل.
  • Changes منظمة.

العيب

بعض Improvements قد تنتظر حتى Release القادمة.

أما Critical Fix فقد يحتاج Release فوري.

Service Pack

Commercial Vendors قد تصدر Maintenance Releases باسم:

Service Pack

ويحتوي Fixes وEnhancements.
